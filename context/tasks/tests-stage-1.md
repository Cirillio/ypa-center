## 2. Ветка `tests` и синхронизация с `preprod`

Факты на 2026-09-28: `preprod` впереди `origin/preprod` на 14 коммитов (не
запушены); в рабочей директории – `CLAUDE.md` (изменён) и
`context/testing-strategy-2026-09.md` (новый).

**Создание**

1. Закоммитить документы на `preprod` (стратегия, правка `CLAUDE.md`, этот файл)
   – это документация, ей место в основной ветке, а не в `tests`.
2. `git switch -c tests` от `preprod`.

**Правила ветки**

- В `tests` меняются только: `tests/`, `vitest.config.ts`, `package.json`,
  `bun.lock`, `.github/workflows/ci.yml`, `.husky/pre-commit`, `context/`.
- Продакшен-код в `tests` не рефакторится «под тесты». Исключение – баг,
  найденный тестом: фикс и падающий до него тест – **отдельным коммитом**
  `fix: …`, чтобы его можно было перенести в `preprod` через `cherry-pick`, не
  дожидаясь мержа всей ветки.
- Синхронизация: `git merge preprod` в `tests` после каждого нового коммита в
  `preprod` и обязательно перед мержем обратно. Merge, не rebase: ветку можно
  будет пушить, история не переписывается.
- Мерж обратно: `tests` → `preprod`, когда пройдены шаги 1–8 и `bun run check`
  зелёный на обеих ветках после синхронизации.

**Где ждать конфликтов**

| Файл                          | Как разрешать                                                  |
| ----------------------------- | -------------------------------------------------------------- |
| `package.json`                | Взять обе стороны вручную                                      |
| `bun.lock`                    | Не править руками: взять версию `preprod`, затем `bun install` |
| `context/progress-tracker.md` | Обе стороны, записи по датам                                   |
| `.github/workflows/ci.yml`    | Шаги тестов из `tests` поверх изменений `preprod`              |

Коммиты и push – только по явной просьбе, сообщения краткие, в одинарных
кавычках, без упоминаний ИИ.

## 3. Соглашения

- Раскладка: `tests/unit/**/*.spec.ts` (node), `tests/nuxt/**/*.nuxt.spec.ts`
  (Nuxt-окружение), `tests/fixtures/dto/*.ts` (фабрики DTO, типизированы из
  `~/types`). Имя файла теста = имя исходника.
- `describe` – модуль, `it` – поведение по-английски; списки граничных случаев –
  `it.each`.
- Строгие типы как в `app/`: без `any`, `as` без проверки, `!`.
- **Часовой пояс тестов – `UTC`**, а не Новосибирск: машина разработчика в
  UTC+7 скрыла бы код, который забыл указать `timeZone` явно. Время – через
  `vi.setSystemTime`, без реальных задержек.
- Деньги проверяются точной строкой, включая пробел-разделитель тысяч,
  который выдаёт `toLocaleString("ru-RU")` (фиксируется первым же тестом).
- Ошибки API – только по `code`.
- Готово для каждого шага: тесты зелёные, `bun run check` зелёный, и тест
  **падает**, если временно сломать проверяемую логику (проверить один раз).

  перед `build`.

  typecheck их не видит – завести `tests/tsconfig.json`, наследующий
  `.nuxt/tsconfig.app.json`, и отдельный шаг `vue-tsc --noEmit -p tests`.
- По одному smoke-тесту в каждом проекте.

**Приёмка:** `bun run test` выполняет оба проекта; ошибка типов в тесте
роняет `bun run check`.

### Шаг 5. Транспорт `useApi` · 3–4 ч · проект `nuxt`

13 случаев из стратегии §5.5. `$fetch` подменяется через `vi.stubGlobal`,
`navigateTo`/`useRouter`/`useAuthStore` – через `mockNuxtImport`. Гонки – на
промисах, которые тест разрешает вручную, без таймеров.

Ключевые: три параллельных 401 → **ровно один** refresh; повтор исходного
запроса – ровно один раз; auth-эндпоинты не рефрешатся; провал refresh →
очистка токенов, `resetFlow`, `/login`; соседняя вкладка уже обновила пару →
без сетевого refresh; с `navigator.locks` и без; `403 PROFILE_INCOMPLETE` →
`/login?redirectFrom=…`, но не на самом `/login`.

Сбрасывать модульный `refreshPromise` между тестами – `vi.resetModules()`.

## 5. Открытые вопросы (появятся по ходу, не блокируют старт)

1. `kopecksToRubles` округляет `Math.round`: 1 500,50 ₽ в модели станет 1 501 ₽,
   а `formatRub` покажет «1 500,5 ₽». Цены центра, вероятно, целые – тест
   зафиксирует текущее поведение, решение за владельцем.
2. Файл `composables/useOptTimer.ts` экспортирует `useOtpTimer`, а
   `useSlotDate.ts` – `useFormatDate`: имена не совпадают. Не баг, в техдолг.
3. Если `nuxt typecheck` не видит `tests/` – отдельный tsconfig (шаг 1).

## Архитектура

### Принцип разделения ответственности

- **Store (`useTrialStore`)** – хранит `selectedClubId`, `selectedSlotId`, `pid`. Только состояние, никакой async-логики.
- **Страница (`enroll/trial.vue`)** – владеет фетчем платежа через `useAsyncData`. Она же решает, какой UI показывать.
- **Сервер** – создаёт платёж, возвращает `confirmationUrl` и `paymentId`. Проверяет статус по `paymentId`.

### Redirect-flow (шаги)

```
1. Пользователь заполнил форму → нажал "Перейти к оплате"
2. POST /api/payments/create { clubId, slotId, ...formData }
   ← { paymentId, confirmationUrl }
3. router.push(confirmationUrl)                  ← переход на страницу ЮКасса
4. Пользователь платит (или нет)
5. ЮКасса редиректит на:
   /enroll/trial?pid=<paymentId>
6. Страница видит pid в URL → useAsyncData фетчит GET /api/payments/:pid
7. По статусу – рендерит нужный UI-блок
```

### Реализация в коде

```ts
// enroll/trial.vue – script setup

const trialStore = useTrialStore()
const { selectedClubId, selectedSlotId, pid } = storeToRefs(trialStore)

const { data: payment, status: fetchStatus } = await useAsyncData(
    "pending-payment",
    () => $fetch(`/api/payments/${pid.value}`),
    { server: true, immediate: !!pid.value }
)

// Заполняем store данными с сервера (без гидрации-конфликта)
if (payment.value) {
    selectedClubId.value = payment.value.clubId
    selectedSlotId.value = payment.value.slotId
}

const isPaymentMode = computed(() => !!pid.value)
```

```html
<!-- Блоки выбора – блокируются при наличии pid -->
<fieldset :disabled="isPaymentMode" :class="{ 'opacity-50 pointer-events-none': isPaymentMode }">
    <!-- RadioCard кружков -->
    <!-- RadioCard слотов -->
</fieldset>

<!-- Правый столбец – анкета или блок оплаты -->
<PaymentStatus v-if="isPaymentMode" :payment="payment" :loading="fetchStatus === 'pending'" />
<UForm v-else ... />
```

## Статусы платежа ЮКасса

### Полная таблица

| Статус                | Значение                                            | Финальный? |
| --------------------- | --------------------------------------------------- | ---------- |
| `pending`             | Платёж создан, ожидает действия пользователя        | Нет        |
| `waiting_for_capture` | Средства захолдированы, ждут подтверждения списания | Нет        |
| `succeeded`           | Оплата прошла, деньги списаны                       | **Да**     |
| `canceled`            | Платёж отменён (пользователем, банком или системой) | **Да**     |

### Причины отмены (`canceled_details.reason`)

| Причина                   | Когда                                                      | Что показать                                              |
| ------------------------- | ---------------------------------------------------------- | --------------------------------------------------------- |
| `expired_on_confirmation` | Пользователь не оплатил за отведённое время (обычно 1 час) | «Время оплаты истекло» + кнопка «Попробовать снова»       |
| `insufficient_funds`      | Недостаточно средств на карте                              | «Недостаточно средств» + «Попробовать снова»              |
| `card_expired`            | Карта просрочена                                           | «Карта недействительна» + «Попробовать снова»             |
| `3d_secure_failed`        | Ошибка 3D-Secure подтверждения                             | «Ошибка подтверждения» + «Попробовать снова»              |
| `payment_method_rejected` | Метод оплаты отклонён банком                               | «Платёж отклонён банком» + «Попробовать снова»            |
| `fraud_suspected`         | Подозрение на мошенничество (со стороны ЮКасса/банка)      | «Платёж отклонён» (без подробностей) + контакты поддержки |
| `internal_timeout`        | Таймаут на стороне ЮКасса                                  | «Технический сбой» + «Попробовать снова»                  |
| `general_decline`         | Общий отказ без конкретной причины                         | «Платёж отклонён» + «Попробовать снова»                   |

### Какие статусы **обязательно** обрабатывать

```
✅ succeeded       – показать подтверждение, записать в БД, отправить письмо/уведомление
✅ canceled        – показать причину, дать возможность повторить
✅ pending         – показать лоадер, запустить polling статуса
⚠️ waiting_for_capture – для двухстадийных платежей; если не используешь capture вручную – не нужен
❌ invalid pid     – pid есть в URL, но платёж не найден на сервере → редирект или ошибка
```

### Polling для `pending`

ЮКасса не присылает ответ мгновенно. Пользователь может вернуться ещё до того, как статус обновился.

```ts
// Простой polling на клиенте (если сервер не использует вебхуки)
const { data: payment } = useAsyncData(...)

watchEffect(() => {
    if (payment.value?.status !== 'pending') return

    const timer = setTimeout(async () => {
        await refreshNuxtData('pending-payment')
    }, 3000)

    onScopeDispose(() => clearTimeout(timer))
})
```

Лучший вариант – **вебхук от ЮКасса на сервер** → сервер обновляет БД → клиент делает один запрос и получает актуальный статус. Polling – только fallback.

## Edge-cases, которые нужно предусмотреть

| Ситуация                                                                    | Поведение                                                              |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Пользователь закрыл страницу ЮКасса без оплаты и вернулся по кнопке «Назад» | `pid` нет в URL → обычная форма                                        |
| Пользователь вручную прописал `?pid=мусор` в URL                            | 404 от API → показать ошибку «Платёж не найден»                        |
| Пользователь обновил страницу пока `pending`                                | Повторный фетч – корректно, `useAsyncData` с `server: true` отработает |
| Пользователь оплатил, но вебхук ещё не пришёл                               | `pending` → polling подхватит обновление                               |
| Двойная оплата (повторный заход с тем же `pid`)                             | `succeeded` → просто показать подтверждение, не создавать новую запись |
